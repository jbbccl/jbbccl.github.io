代码审查：BFS 层级计数存在 Bug

核心问题：层级边界更新位置错误

if(l >= ub) 的检查和 ub = r 的更新发生在处理当前节点的邻居之前，导致 ub 没有包含当前节点所贡献的下一层邻居。

反例

考虑以下树结构，从节点 1 出发，L=1（期望输出 3）：

逐步跟踪

步骤curlrubcv说明
初始—0110队列: [1]
111110出队后 l>=ub 触发
→1→1⚠️ ub=r=1（邻居还没加！）
→3才加入 2,3
222311l>=ub(2≥1)又触发！
→3→2cv=2 > L=1 → break

输出 l=2，但正确答案是 3

原因

当某层最后一个节点出队时，ub = r 获取的值不包含该节点即将加入的邻居，导致边界过早收缩

修复

将层级边界检查移到邻居处理之后：

输出 l=3 ✅ （节点 1, 2, 3，恰好第 0 层 + 第 1 层）
